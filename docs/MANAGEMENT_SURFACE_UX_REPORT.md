# 관리 화면·Ask Agent 사용성 판단 보고서

## 목표와 완료 범위

- Note는 작업 중 문맥을 유지하는 워크스페이스 보조 패널로 남긴다.
- Automation은 워크스페이스에 속한 장기 체류 관리 페이지로 전환한다.
- Status Widget은 서버 전체 설정이므로 전역 관리 페이지로 전환한다.
- 세 화면의 Ask Agent는 모달을 추가로 띄우지 않고 현재 패널·페이지 안의 하위 화면으로 전환한다.
- 기존 버튼과 메뉴 진입점은 유지하면서 URL, 브라우저 뒤로가기, 새로고침, 포커스 복귀, 모바일 화면을 지원한다.

## 확정한 제품 정책

### 화면 소유권

- Note: 현재 워크스페이스 패널. 요청은 해당 워크스페이스의 Main Agent에만 보낸다.
- Automation: `/workspaces/:id/automations`. 요청은 URL이 가리키는 워크스페이스의 Main Agent에만 보낸다.
- Status Widget: `/settings/widgets?workspace=:id`. 위젯 파일은 전역이지만 작업 에이전트는 워크스페이스에 있으므로 화면 안에서 대상을 명시적으로 선택한다.

### Widget 전송 대상 기본값

지원되는 에이전트가 Main 터미널에서 실행 중인 워크스페이스만 선택지에 포함한다. 현재 워크스페이스가 대상이면 우선 선택하고, 아니면 마지막 활동 시각이 가장 최근인 대상 워크스페이스를 선택한다. 자동 선택되더라도 `Send to` 선택기를 항상 보여 사용자가 전송 위치를 확인하고 바꿀 수 있게 했다.

### 미저장 변경과 전송

Widget 설정에 미저장 변경이 있으면 Ask Agent를 비활성화하고 먼저 저장하도록 안내한다. 자동 저장이나 변경 폐기는 사용자의 설정을 조용히 확정하거나 잃게 할 수 있어 사용하지 않았다. 저장이 끝나면 관리 페이지를 닫지 않고 저장·Ask Agent 상태만 즉시 갱신한다.

Note의 일반 편집은 패널을 닫아도 마운트를 유지해 자동 저장을 계속하고, 워크스페이스 교체·관리 페이지 진입·브라우저 탐색처럼 편집기를 제거하는 전환은 저장 성공을 기다린다. 저장 실패 시 현재 워크스페이스와 방문 기록을 유지해 사용자가 오류를 확인하고 다시 시도할 수 있다. Note의 에이전트 전송, Automation 변경·전송, Widget 저장·전송 중에는 해당 관리 화면을 닫거나 바꾸지 못하게 한다. 요청이 중간에 사라졌는지 판단하기 어려운 상태를 만들지 않기 위한 정책이다.

Widget의 미저장 변경은 닫기, 브라우저 뒤로가기, 사이드바 이동, 숫자 단축키, 새 워크스페이스 생성 모두 같은 확인 절차를 거친다. 취소하면 편집 내용과 방문 기록을 그대로 유지하고, 폐기를 확인했을 때만 원래 요청한 이동을 실행한다.

### 모달 제거와 탐색

Note, Automation, Widget의 Ask Agent 사용 경로에는 `dialog`를 중첩하지 않는다. 하위 화면의 뒤로가기는 원래 편집·목록 화면과 트리거 포커스를 복구한다. Automation과 Widget은 실제 URL을 가지며 직접 접속·새로고침할 수 있다. 앱에서 진입한 관리 페이지는 닫기와 브라우저 뒤로가기로 원래 워크스페이스로 복귀한다.

## 기존 사용자 호환성

- 기존의 `Agent automations`, `Manage status widgets`, `Ask agent…` 진입 이름은 유지한다.
- 기존 Automation CRUD, 1회·간격·요일 반복 계약과 API는 바꾸지 않는다.
- 기존 Note 자동 저장과 에이전트 전달 API를 유지한다.
- 기존 Widget 저장 형식, 순서 변경, 프리셋, 전역 공유 동작을 유지한다.
- 변경점은 관리 UI가 모달 대신 패널·페이지에 머물고, Widget 저장 뒤 화면이 유지되는 것이다.

## 사용자 판단이 필요했거나 애매했던 항목

### Widget 대상 기본값을 기억할지

현재는 화면을 열 때 `현재 대상 → 최근 대상` 순서로 계산하고 별도 사용자 선호로 저장하지 않는다. 사용자가 항상 특정 워크스페이스의 에이전트에게 전역 작업을 맡기길 원한다면 마지막 선택을 브라우저 또는 서버 설정으로 기억하는 정책을 추가할 수 있다. 지금 정책은 오래된 선택이 보이지 않게 재사용되는 위험보다 현재 실행 상태를 우선한다.

### Ask Agent 하위 화면을 URL에 포함할지

Automation과 Widget의 관리 페이지 URL은 영속하지만 `Ask Agent가 열린 상태`까지 별도 URL로 만들지는 않았다. 새로고침하면 관리 목록으로 돌아간다. 요청 초안 복원이나 Ask 화면 공유 링크가 필요해지면 `/ask` 하위 경로와 초안 저장 정책을 별도로 정해야 한다.

### Widget 최대 개수 상태의 Ask Agent

수동 `Add widget`은 최대 개수에서 제한하지만 Ask Agent는 계속 사용할 수 있게 했다. 에이전트가 기존 위젯 수정·교체·삭제도 할 수 있기 때문이다. 새 위젯만 추가하려는 요청은 기존 검증기가 최대 개수 초과를 거절한다. 제품 문구를 `Create`에서 `Manage`로 넓힐지는 후속 카피 결정 사항이다.

### 인식 가능한 Main Agent가 없을 때

Widget 화면은 대상 선택과 Ask Agent를 비활성화하고 실행 중인 지원 에이전트가 필요하다고 안내한다. 임의 셸이나 백그라운드 터미널로 보내지 않는다. 지원할 에이전트 프로세스 이름의 범위는 기존 인식 정책을 그대로 따른다.

## 릴리즈 정책

이번 변경은 요청에 따라 `main`에만 반영하고 버전 번호와 릴리즈 태그는 변경하지 않는다. 다음 배포 범위에 포함할지는 별도 릴리즈 판단으로 남긴다.

## 검증과 리뷰

- `pnpm check`: 아키텍처, 디자인 시스템, Svelte/TypeScript 진단 통과.
- `pnpm test:node`: 293개 통과.
- `pnpm test:component`: 73개 통과.
- `pnpm build`: 프로덕션 빌드 통과.
- `pnpm test:e2e`: 데스크톱 Chromium, 터미널 인계 Firefox, 모바일 Chromium/Firefox의 47개 시나리오 통과.
- 별도 회귀 검증: Note 저장 지연·실패 후 workspace 이동/방문 기록 보존, Widget 미저장 X·뒤로가기·숫자 단축키, 모바일 관리 화면·포커스, Git discard 갱신 경합.
- 팀 에이전트 리뷰: UI, 릴리즈, 서버 관점에서 여러 차례 재검토했다. 최종 Blocker/Important가 없는 상태에서 release-ready 판정을 받았다.

리뷰 중 발견해 함께 수정한 범위는 관리 화면 밖에서 드러난 Git discard 직후 목록 갱신 경합과 터미널 재연결의 포커스 탈취다. 둘 다 새 관리 흐름의 실제 사용·회귀 테스트에서 재현됐고, 관련 모델·브라우저 테스트를 추가했다.
