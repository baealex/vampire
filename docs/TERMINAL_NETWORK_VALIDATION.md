# 원격 연결·저장소 검증

## 최종 결과

- Node 테스트 421개 통과.
- 컴포넌트 테스트 32개 파일·176개 통과.
- 실제 브라우저의 서로 다른 22개 시나리오 통과(여러 실행으로 검증, 중복 실행은 제외).
- `pnpm check`: 아키텍처·디자인 시스템·Svelte/TypeScript 검사 통과, 오류·경고 0개.
- production build, `pnpm format:check`, `git diff --check` 통과.

재현된 연결·출력 적체·저장소 과잉 처리 문제의 코드 수정과 자동 검증을 완료했다. 운영 서비스 적용과 실제 모바일·무선·장시간 조건 검증은 수행하지 않았다.

## 시험 환경

로컬 production build, 실제 Git·tmux, 실제 브라우저와 TCP 중계기를 사용했다. 실행 중인 사용자 서비스나 사용자 tmux 세션에는 적용하지 않았다.

중계기는 각 TCP 연결의 양방향 바이트 스트림에 대역폭과 지연을 적용한다. WebSocket뿐 아니라 페이지와 API도 이 경로를 지난다. 읽기 중단으로 송신 측에 역압력을 전달하고 중계 대기열을 제한한다. **기기 전체의 공유 대역폭, TCP ACK·패킷 손실·재전송, TLS, 통신사 망은 모사하지 않는다.** 표의 지연은 양쪽 페이로드 지연의 합이다.

페이지 동결은 Chromium lifecycle의 `frozen`/`active` 전환이다. 모바일 Chromium·Firefox·WebKit은 데스크톱 호스트의 브라우저 엔진에 모바일 크기·터치 설정을 적용했다. 실제 iOS/Android의 앱 절전·메모리 회수·Wi-Fi↔셀룰러 이동을 검증한 결과는 아니다.

## 검증 계약

| 시험 | 확인 사항 |
| --- | --- |
| 연결별 1Mbps·300ms, ANSI 출력, 3초 단절 | 새 연결의 ready 수신, 최종 tmux 화면 일치, 후속 입력 전달 확인, 단일 기기 제어권 유지 |
| 연결별 256Kbps·1초, 같은 출력·단절 | 위와 동일 |
| 연결별 256Kbps·1초, 20초 단절 | 재시도 소진 이벤트 후 online 복귀로 회복, 후속 입력·최종 화면 일치 |
| 브라우저 5초 동결 중 500행 출력 | 복귀 후 최신 화면과 작성 중인 초안 보존 |
| 4기기 중 1대만 256Kbps·1초, 약 3.1MB/4초 출력 | 모든 화면이 최신 tmux와 일치, 후속 입력 확인, 기기당 연결 1회, 느린 기기도 출력 시작 후 15초 내 최신 화면 도달 |
| 이미 지속 출력 중인 터미널에 최초 접속 | 연결을 반복하지 않고 화면 준비, 출력 완료 후 tmux와 일치, 잘못된 제어권 안내 없음 |
| 20회 워크스페이스 전환 | 매 전환의 새 권위 스냅샷, 초안·제어권 보존 |
| 지연된 초기 스냅샷·명령 확인 응답 유실 | 화면 복원, 미확인 초안 보존, 명령 자동 재전송 없음 |
| 단일 기기의 이전 서버 소켓이 남은 재접속 | 이전 연결 교체, 잘못된 `Use this device` 없음, 실제 다른 기기 제어권은 재접속으로 빼앗지 않음 |
| 빠른 전체 화면 재그리기·반복 크기 변경·제어권 인계 | 브라우저와 tmux 화면 일치, 올바른 소유자 유지 |
| 로컬 100프레임 ANSI·유니코드 지속 출력 | 전송 표식 100개 확인, 최종 화면·후속 입력 일치, 재접속 없음 |
| 모바일 3개 엔진의 반복 TUI 크기 변경·재접속 중 조합 입력 | 화면 정합성과 입력 보존 |
| 저장소 파일 추가·이동·Git 변경 취소·느린 파일 열기 | 실제 파일 작업 성공, Git 결과 반영, 상태 갱신이 진행 중인 파일 열기를 재시작하지 않음 |

화면 정합성은 매 프레임이 다른 내용을 출력하게 한 뒤 실제 tmux의 현재 행과 브라우저의 행을 비교한다. 중간 완료 표식은 화면 크기 변경으로 현재 viewport 밖으로 나갈 수 있으므로, 느린 기기에 해당 표식이 계속 보일 것을 요구하지 않는다. 이 기준을 변경하기 전의 실패는 복구 실패로 집계하지 않았다. 수정 후에는 최신 상태와 후속 입력을 모두 확인하며, 연결 횟수와 도달 시간도 별도 assertion으로 검사한다.

## 전송 제어 수정 전후

| 관측 | 수정 전 | 수정 후 반복 관측 |
| --- | ---: | ---: |
| 빠른 기기들의 최신 화면 도달 | 약 4.4초 | 약 4.4~4.5초 |
| 느린 기기의 최신 화면 도달 | 26,814ms | 4,892 / 7,392 / 5,035 / 5,406ms |
| 4기기의 연결 횟수 | `[1, 1, 1, 2]` | `[1, 1, 1, 1]` |
| 후속 입력 이후 최종 tmux 화면 일치 | 4대 모두 일치 | 4대 모두 일치 |

시간은 약 4초 길이의 출력 작업 시작부터 측정했다. 수정 후 수치는 여러 로컬 실행의 관측값이며 원격 환경 전체에 대한 백분위나 최대 지연 보장이 아니다. 실제로 보낼 수 없는 양의 중간 출력을 누적하는 대신, 각 기기의 수신 확인 후 최신 상태를 동기화한다. 명령 입력의 재전송 정책은 바꾸지 않았다.

## 초기 조사에서 측정한 기준값

아래는 전송 제어 수정 전 초기 조사값이다. 이후 같은 회복 계약을 회귀 검증했으며, 이 수치를 최종 코드의 새 성능 측정치로 해석하지 않는다.

| 조건 | 페이지 진입부터 준비 | 단절 해제부터 새 ready 수신 |
| --- | ---: | ---: |
| 1Mbps·300ms, 3초 단절 | 5,618ms | 1,871ms |
| 256Kbps·1초, 3초 단절 | 16,832ms | 2,878ms |
| 256Kbps·1초, 20초 단절 | 16,907ms | 1,890ms |

페이지 진입 시간에는 HTML·JS·API와 터미널 접속이 포함된다. 기존 화면의 CSS 준비 상태가 아니라 **새 연결의 ready 진단 이벤트**로 복구 시간을 측정한다. 20초 단절에서는 예산 소진 이벤트 1회가 확인됐다.

과거 warm cache를 사용한 20회 전환 관측은 중앙값 46.5ms, 최대 869ms였지만 현재 구현의 성능 기준으로 사용하지 않는다. 현재는 전환할 때마다 새 터미널 연결과 권위 스냅샷을 요구해 숨겨 둔 xterm 상태보다 화면 정합성을 우선한다. 브라우저 5초 동결 후 화면 복귀에 대한 과거 관측은 154ms였으며, 실제 휴대전화 절전·장시간 사용의 측정값이 아니다.

## 저장소 부하 검증

[안정화 검토](TERMINAL_RELIABILITY.md)의 Git 비교에서는 새 파일 500개 기준 509회 → 11회, 2,000개 기준 2,009회 → 11회로 프로세스 실행이 줄었다. 실제 Git 인덱스의 바이트 동일성, 스테이징·작업 파일 구분, 바이너리 속성, 개행 없는 파일, 공백·개행·대괄호 파일명을 검증했다.

브라우저 상태 테스트는 접은 폴더와 자손을 재조회하지 않는지, 다시 펼칠 때 최신 내용을 읽는지, 폴더 갱신 중 삭제된 경로를 처리하는지, 워크스페이스 해제 시 요청 취소와 예약 갱신 중단이 이루어지는지 확인한다. 서버 테스트는 동시 스냅샷·폴더 조회가 진행 중 작업을 공유하되 후속 변경은 새로 읽는지 확인한다.

## 재현 명령

```sh
pnpm test
pnpm exec playwright test --project=desktop-chromium -g 'network reliability|recovers delayed terminal|lingering previous|sustained tmux output|hands terminal layout|rapid full-screen redraws|lost acknowledgement|adds and moves files|discards tracked and untracked|slow file open'
pnpm exec playwright test --project=mobile-chromium --project=mobile-firefox --project=mobile-webkit -g 'preserves mobile composition through a reconnect snapshot|keeps a full-screen TUI coherent through repeated mobile resizes'
```

시험 소스는 `e2e/desktop.spec.ts`, `e2e/mobile.spec.ts`, 중계기는 `e2e/terminal-network.ts`다. 네트워크 진단 JSON은 해당 Playwright 테스트 결과 디렉터리에 저장한다. 다른 실행을 시작하면 이전 결과 디렉터리가 정리될 수 있으므로 비교할 기록은 먼저 보존한다.

## 남는 검증 범위

실제 모바일 운영체제의 절전·메모리 회수, 실제 무선 망 이동·공유 회선 혼잡·패킷 손실, 수 시간·수 일 사용, 모든 에이전트 TUI와 깊은 히스토리 조합은 확인하지 않았다. 이 한계와 재현된 결함의 코드 수정 완료를 구분한다. 사용자 서비스의 배포·재시작은 수행하지 않았다.
