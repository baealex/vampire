# 자동화 에이전트·반복 일정 구현 판단 보고서

## 목표와 완료 범위

- 자동화 화면에서 자연어 요청을 현재 워크스페이스의 메인 에이전트로 보내고, 에이전트가 검증된 요청 파일을 통해 새 자동화를 추가할 수 있게 한다.
- 기존 1회·고정 간격 반복을 유지하면서, 요일 복수 선택과 현지 시각·IANA 시간대를 저장하는 주간 반복을 추가한다.
- 저장 계약, 런타임 실행, UI, 에이전트 지원 파일, 단위·컴포넌트·E2E 검증을 함께 변경한다.

## 주요 판단

### 전체 세션 저장 파일을 에이전트에 직접 편집시키지 않음

세션 저장 파일에는 여러 워크스페이스의 실행 상태와 내부 자동화 큐가 함께 들어 있다. 에이전트가 이 파일을 직접 수정하면 서버 저장과 충돌하거나 다른 워크스페이스 데이터를 훼손할 수 있다.

대신 요청마다 격리된 초안 파일과 현재 계약 가이드, 검증·적용 명령을 만든다. 적용 명령은 완성된 파일만 원자적으로 스테이징하고, 실행 중인 서버가 이를 가져와 기존 저장소 변경 경로로 저장한다.

### 요청별 경로와 영속 요청 ID 사용

같은 워크스페이스에서 이전 요청을 에이전트가 처리하는 동안 다음 요청이 들어올 수 있다. 동일 초안 경로를 재사용하지 않고 요청별 경로를 발급한다. 요청 ID를 생성된 자동화에도 기록해, 저장 직후 프로세스가 종료되어 스테이징 파일이 남더라도 재시작 후 같은 자동화가 중복 생성되지 않게 했다.

### 사용자 자동화 한도와 내부 전달 큐 분리

사용자 자동화 최대 32개는 화면에 보이는 `custom` 자동화에만 적용한다. Ask Agent와 노트 요청처럼 내부 전달에 쓰이는 고정 개수 항목은 별도 저장 여유로 계산한다. 31개 상태에서 Ask Agent로 32번째 자동화를 만드는 경계를 테스트한다. 이미 32개가 가득 찬 경우에는 에이전트 요청을 보내기 전에 거절한다.

에이전트에 전달된 자동화 초안은 완성될 때까지 사용자 자동화 슬롯 하나를 예약한다. 예약, 수동 생성, 다른 에이전트 요청을 같은 저장소 변경 잠금으로 직렬화하고 초안·적용 대기 파일 수도 한도에 포함했다. 따라서 31개 상태에서 에이전트 요청을 보낸 직후 수동 생성이나 두 번째 요청이 32번째 슬롯을 빼앗을 수 없다. 요청 전달 자체가 실패하면 초안을 지워 예약도 즉시 해제한다.

초안에서 적용 대기 파일로 바뀌는 동안 두 파일이 잠시 함께 있거나 프로세스가 중단될 수 있으므로 파일 수가 아니라 고유 요청 ID 수로 예약을 센다. 가져오기가 끝나면 남아 있는 양쪽 파일을 모두 정리한다.

### 주간 반복은 시간대가 있는 달력 일정으로 저장

요일만 저장하고 서버 또는 브라우저의 현재 시간대를 사용하면 다른 기기나 일광절약시간 변경 뒤 실행 시각이 달라진다. 주간 반복은 요일, 시·분, IANA 시간대, 시작 하한을 함께 저장한다. 목록에도 시간대 이름을 표시한다.

## 사용자 판단이 필요했거나 애매했던 항목

### 일광절약시간에 존재하지 않는 시각

현재 정책은 선택한 지역에서 존재하지 않는 현지 시각을 건너뛴다. 예를 들어 `America/New_York`의 봄 전환일에 02:30이 사라지면 그 주 일요일 실행은 생략되고 다음 선택 요일로 넘어간다. 가을에 같은 시각이 두 번 생기면 첫 번째 시각에 한 번만 실행한다.

대안은 존재하지 않는 시각을 당일의 다음 유효 시각(예: 03:00)으로 미루는 것이다. 어느 쪽도 보편적으로 정답은 아니며, 현재는 중복·예상 밖 지연 실행보다 달력 시각의 엄격한 일치를 우선했다. 제품 정책을 바꾸려면 이 항목을 기준으로 결정하면 된다.

### 이번 범위는 새 자동화 생성

Ask Agent는 자연어로 새 자동화를 추가하는 흐름까지 제공한다. 기존 자동화의 프롬프트·일정을 에이전트로 수정하거나 여러 자동화를 한 번에 삭제하는 기능은 포함하지 않았다. 수정까지 열려면 대상 ID 선택, 동시 수정 충돌, 변경 전후 확인 UX를 별도 계약으로 정해야 한다.

### 완료되지 않은 에이전트 초안의 예약 수명

에이전트 요청을 전달하면 해당 초안은 자동화가 적용되거나 요청 전달이 실패할 때까지 슬롯 하나를 예약한다. 에이전트가 요청을 받았지만 적용 명령을 실행하지 않고 작업을 끝내는 경우를 위해 초안의 마지막 수정 후 24시간이 지나면 다음 용량 확인에서 자동 만료·삭제한다. 에이전트가 초안을 편집하면 파일 수정 시각이 갱신되어 작업 중인 요청의 만료도 연장된다. 워크스페이스를 삭제할 때는 해당 워크스페이스의 초안·적용 대기·격리 파일도 함께 제거한다.

24시간은 정상적인 에이전트 작업에 충분한 여유를 주면서 영구 슬롯 잠금을 막기 위한 현재 제품 정책이다. 장기 실행 에이전트를 공식 지원하거나 사용자가 즉시 되돌려야 한다면 대기 요청 목록과 명시적 취소 UI를 추가해야 한다.

적용 전 계약 오류는 에이전트가 실행하는 검증 명령에서 즉시 실패한다. 서버 가져오기 시점에 워크스페이스가 이미 삭제되었거나 내부 저장 오류가 발생하면 요청 파일은 삭제하지 않고 `.rejected-*`로 격리한다. 현재 UI에는 이 드문 실패를 별도 알림으로 노출하지 않는다.

## 검증과 리뷰

- `pnpm check:architecture`
- `pnpm check`
- 전체 Node 테스트
- 전체 컴포넌트 테스트
- 프로덕션 빌드
- 자동화 생성·Ask Agent 전달 데스크톱 E2E
- 독립 리뷰에서 발견된 요청 경로 경쟁, 중복 가져오기, 저장 한도·예약 경쟁, draft/ready 중복 집계, 미완료 예약 수명, 시간대 기대값 문제를 수정하고 각각 회귀 테스트를 추가

최종 결과는 Node 테스트 291개, 컴포넌트 테스트 60개, 프로덕션 빌드와 대상 데스크톱 E2E가 모두 통과했다. 서버, UI, 릴리즈 관점의 세 독립 리뷰도 수정 후 Blocker/Important 잔여 없음과 `release-ready: YES`로 판정했다.
